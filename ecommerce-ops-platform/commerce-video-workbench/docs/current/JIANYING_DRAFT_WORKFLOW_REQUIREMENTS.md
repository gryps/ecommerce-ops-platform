# 原视频归类、资源库与剪映草稿工作流规范

> 生效日期：2026-08-01
>
> 本文取代旧人工粗剪、音乐卡点、系统内精修、成片渲染与热播工作流。

## 1. 工作流

```text
原视频确认归类并移动
→ 文案/语音/音乐资源准备
→ 人工选择文案、字幕/旁白和背景音乐
→ 直接生成无视频轨道的剪映草稿
→ 在剪映专业版继续编辑
```

## 2. 原视频归类

1. 页面分为“产品与标签管理”和“素材归类”两个标签页。
   “产品与标签管理”中，大量产品使用左侧独立清单，标签分类与标签名称在右侧并列区域展示；各清单独立滚动，不能因产品数量增加而把标签管理入口推到页面底部。
2. 产品名称、标签分类、标签名称支持新增、分页查看、修改和直接删除；产品与标签管理使用各自的新增名称输入框直接联想查询已有数据，不另设重复的产品或标签查询框；归类页的三个输入框也支持下拉选择、模糊输入和单独保存，未保存输入不能参与归类。标签分类与标签名称必须提供明确的下拉按钮，展开列表和重新选择时不能要求用户先删除已有输入。
3. 标签是跨产品通用主数据，以“标签分类＋标签名称”共同保证唯一；标签只允许改名，不能调整所属分类；删除分类同时删除其全部标签和视频标签关系。
4. 人工先选择或保存产品，再选择同一产品的一组视频；确认前切换产品不清空视频和标签，因为此时尚未建立关系。
5. 视频默认不选中，提供全选和取消全选；标签可应用到单个或批量选中的视频。每条视频在同一标签分类下只能选择一个标签名称，再选同分类的其他名称会替换原选择；不同分类的标签可以同时存在；点击全部选中视频都已有的同一标签会统一移除。
6. 每条视频至少有一个标签后才允许确认归类；前端和后端都必须拒绝同一视频在同一分类下出现多个标签名称。
7. 用户通过 Windows 标准文件窗口选择一个或多个视频；系统不得复制视频或创建等待粗剪的代理。
8. 目标目录固定为所选素材根目录下的产品名称文件夹；文件名固定为“产品-标签1-标签2”，不包含标签分类名称，重名时追加数字序号。
9. 文件名中的 Windows 非法字符必须安全替换，不能允许路径穿越。
10. 移动前检查源文件、目录边界、扩展名、媒体信息和标签完整性；批量移动中途失败时回退本批已经移动的文件。
11. 移动成功后记录原路径、现路径、媒体信息、产品和标签。
12. 确认归类只负责本次移动与重命名；不追踪或回退后续文件变化，已归类文件允许再次选择并重新归类。
13. 修改或删除主数据不移动、不改名磁盘上的既有视频。
14. 页面不展示长期本地归类历史清单；本次操作成功后停留在“素材归类”，仅在该标签页上方提示栏显示本次移动数量和移动后的文件名，页面刷新后可清除该临时结果；操作结果不能显示到“产品与标签管理”。
15. 产品、标签分类和标签名称的删除确认统一使用页面中央弹窗；弹窗必须明确删除对象和关系影响，并保留取消操作，不能依赖位置不可控的浏览器原生确认框。
16. “确认归类并移动”提交后必须显示明确的执行中状态并禁用重复提交；浏览器刷新后要恢复原操作状态，直到移动完成或失败，不能把刷新误判为操作结束。

## 3. 内容文库

1. 内容文库分为“文案”“音色库”“旁白与字幕”三个二级标签页，音色库固定排在第二位；短标题和长口播稿统一属于文案。
2. 用户可以输入一条参考文案，也可以留空。输入后，百炼模型自动分析语言风格、用词偏好、情感基调、诉求重点，并推断受众年龄、性别、兴趣、消费水平和心理状态；专家角色由模型自由推荐，分析结果和角色不提供人工修改。
3. 分析完成后自动生成 5 条仿写。短文案保持短文案形态，长口播稿保持相近长度。用户输入的参考原文同时自动进入文案库，状态为已采纳。
4. 未输入参考文案时，系统只使用全局已采纳文案形成的历史语料进行分析和推荐；没有任何已采纳文案时必须阻止生成并提示先输入参考文案。
5. 每条模型文案独立采纳或不采纳，允许部分采纳；不采纳必须填写原因。完成当前 5 条审核后，才能继续迭代 5 条，后续迭代沿用固定的参考资料、分析、专家角色及此前审核反馈。
6. 每次任务的参考资料、分析、专家角色和各轮生成结果保存在“分析与迭代记录”，最新在前，每页 10 条。删除记录只删除分析与迭代过程，已经进入文案库的参考原文和采纳文案必须保留。
7. 文案库只展示已采纳内容，不在每条内容上重复展示复杂的来源分析；文案支持修改和中央确认后删除。候选历史与文案库条目是独立数据，删除文案库条目不删除迭代历史，也不改写已生成剪映草稿中冻结的文案快照。
8. “文案”标签页包含“音频转文案”：允许提交抖音视频短链接、本地视频或本地音频，调用语音识别模型得到可修改文字；只有人工点击保存后才进入文案库，不创建旁白资源。
9. “旁白与字幕”标签页只保留字幕配音和旁白与字幕库。配音文案既可手动输入，也可通过模糊联想输入框从文案库选择；联想查询直接请求全部文案库并只返回少量匹配项，不受页面预载条数限制，选择后自动填入正文。输入音色库序号后调用语音合成模型生成旁白。
10. 旁白与字幕经人工确认后才能用于剪映草稿。
11. 文案分析、根据已采纳文案推荐和继续迭代提交后必须显示执行中状态并禁用重复提交；浏览器刷新后继续查询原操作，不能因页面内存状态丢失而允许重复调用模型。
12. 分析与迭代记录的内容必须紧接在所查看条目的下方展开；同一个条目按钮在“查看／收起”之间切换，不能重复放置收起按钮，查看另一条记录时直接切换内容。
13. 音色库每条音色提供固定短句试听；首次试听才调用模型，成功音频以序号、名称、voice、模型、文件路径和字节数入库并持久保存，后续试听直接复用已入库文件。重复点击当前音色停止试听，切换音色先停止上一段。
14. 当前 `qwen-audio-3.0-tts-plus` 目录采用官方基础音色表固定序号 1–597；字段为序号、名称、voice 参数、性别、年龄、特质、适用场景和音色试听。关键词查询覆盖除“音色试听”外的目录全部字段；性别、年龄、适用场景另设独立下拉筛选，年龄选项按数值从小到大排列；每页 20 条。
15. 字幕配音必须输入音色序号。有效序号自动解析并显示对应名称、voice 参数和属性，提交时后端再次按序号解析；无效或空序号不得生成。不再提供系统/附加音色栏。
16. 模型合成的旁白使用已知文案正文按音频时长生成字幕时间轴，不反向调用音频转文案模型；生成结果可以试听、确认和删除。
17. 音频转文案使用百炼 `qwen3-asr-flash` 非实时模型，通过 OpenAI 兼容 `chat/completions` 的 Base64 `input_audio` 调用；输入预处理为16kHz单声道MP3，并遵守单次5分钟、10MB限制。读取模型列表时只列出兼容该同步 HTTP 协议的基础模型和日期快照，必须排除 `qwen3-asr-flash-realtime` 与 `qwen3-asr-flash-filetrans`；保存配置和实际调用前均再次校验。百炼返回429、可恢复5xx或临时网络错误时最多自动尝试3次，每次真实调用均保留相同业务调用编号和独立尝试序号。
18. 所有会在后端执行媒体脚本或调用模型的操作，都必须在提交后立即显示明确的处理中状态，禁用输入和重复提交，并在完成或失败后恢复；不能只依赖最终的全局成功或错误提示。当前包括归类移动、文案分析与迭代、音频转文案、音色试听、旁白配音、音乐提取与上传、剪映草稿生成及模型列表读取。

## 4. 背景音乐

1. 支持上传常见音频文件和包含音频的视频文件。
2. 支持填写短视频分享链接并自动分离音频。
3. 用户必须确认拥有音频使用权。
4. 音乐可试听、改名、添加和移除自定义标签，也可删除；被剪映草稿引用时禁止删除。标签编辑使用与删除确认框一致的居中弹窗，但采用主操作绿色。试听使用单播放器：重复点击当前音乐停止播放，点击其他音乐先停止上一首，禁止多路音频叠加；加载中和播放失败必须给出可见状态。
5. 链接受登录或平台限制时提示改用上传，不阻塞其他资源。短视频链接提取与本地上传分别维护音乐名称，提交处理期间显示状态并禁止重复提交；接近全静音的提取结果不得标记为可用音乐。抖音页面包含多个媒体流时，应优先独立 `audio`/`ies-music` 背景音乐资源，其次才从真实视频标签逐个验证候选音轨，不得直接采用首个静音占位流。
6. 当前流程不分析或保存 BPM、节拍点、波形及音乐卡点数据。

## 5. 剪映草稿

1. 用户不选择产品和视频，只选择文案、字幕/旁白和背景音乐；系统不写入视频素材或视频片段。为兼容当前剪映时间线，草稿可保留空视频轨道，视频片段由用户进入剪映后人工添加。
2. 文案、字幕/旁白和背景音乐均允许不选，但一次生成至少选择一种物料。
3. 草稿总时长取已选物料中“字幕最后结束时间、旁白音频时长、背景音乐时长”的最大值；文案没有独立时长，不参与最大值计算。仅选择文案且无时间属性物料时，系统创建 5 秒最小草稿。
4. 旁白和背景音乐短于草稿总时长时保持原始长度，不循环、不拉伸、不补静音。
5. 文案写入独立文字轨道，从 0 秒持续显示至旁白真实音频或有效字幕结束；仅有文案或仅有背景音乐时，文案最多显示 5 秒。
6. 字幕写入另一条独立文字轨道，使用资源库中现有时间轴，不重新识别，也不根据旁白或背景音乐重新对齐；如果字幕时间轴异常长于旁白音频，则按旁白真实音频时长裁剪。
7. 生成前自动检测本机剪映草稿目录，向用户展示完整路径并等待确认。
8. 自动检测失败时允许人工填写目录；目录校验通过后持久保存，并在后续生成时优先使用。
9. 草稿直接写入确认后的目的目录，不生成 ZIP；旁白和背景音乐复制到草稿本地 `assets/audio`，音频轨道引用草稿内本地资源。
10. 输出至少包含 `draft_content.json`、`draft_info.json`、`draft_meta_info.json` 和使用说明。
11. 不覆盖已有同名目录，自动追加 `-2`、`-3` 等递增序号。
12. 草稿名称自动追加 `YYYYMMDD-HHMMSS` 时间戳。
13. 剪映草稿记录分页显示，每页最多 20 条；记录支持删除，删除只移除工作台记录，不删除磁盘上的草稿文件夹。
14. 剪映草稿页面三库条目可以省略显示，但鼠标悬浮必须展示完整文案、旁白、音乐名称或标签信息。
15. 使用相同文案、旁白与字幕、背景音乐组合再次生成草稿时，必须弹窗提示此前已生成次数；提示不阻止继续生成。该次数来自独立累计生成计数器，不随草稿记录删除而减少。弹窗必须提供计数器复位按钮，复位只重置当前组合后续重复提示计数，不删除草稿记录。
16. 目录检测、目录确认和草稿生成必须显示明确状态、禁止重复提交，并在完成或失败后恢复。
17. 剪映客户端版本可能升级草稿结构，最终兼容性以当前安装版本验收。

## 6. 模型配置

1. 当前流程统一使用阿里云百炼兼容连接。
2. 文案生成配置一个独立模型 ID，负责文案分析、5 条迭代与字幕文案。
3. 语音模型分为音频转文案和字幕配音，可分别配置模型 ID。
4. 三项功能可复用接口地址和 API Key。
5. 字幕配音只使用音色库序号解析出的 voice 参数；模型配置不维护附加音色 ID。
6. 模型配置按文案生成、语音识别、字幕配音从上到下纵向展示；每张配置卡分别维护百炼连接、独立读取模型列表、独立保存，保存时只更新当前功能；不提供统一配置或跨卡复用连接。
6. 音色列表读取本身不计入真实业务调用；点击音色试听会实际调用字幕配音模型，应记录为真实模型调用。
7. Qwen-Audio-TTS 与 CosyVoice 必须使用百炼工作区原生非实时语音合成接口；不能把模型配置中的兼容模式地址直接拼成 OpenAI `/audio/speech`。非流式响应中的临时音频 URL 下载后才交给页面试听或保存为旁白。
8. 模型配置不提供启用复选框；模型 ID、接口和密钥配置完整后即用于对应功能。读取模型列表后，“模型类别”必须显示可直接选择的下拉选项。
9. 真实调用遵守 `../engineering/model-call-logging-requirements.md`。

## 7. 明确退役

- 人工粗剪与粗剪代理。
- 音乐节拍方案和卡点生产。
- 自动选片、同质化检查和系统内时间线精修。
- 成片渲染、成片库、短链接热播识别与表现状态。
- 无人值守自动生产。
- 框架库及框架布局功能。

退役实体不保留在当前数据库和 ORM 中；仅保留历史迁移文件，使旧数据库可以升级到当前结构。

## 8. 当前开发状态

无视频剪映草稿生成已于 2026-08-03 完成工程实现并通过自动化验证。当前规范以第 5 节为准。

# AI 模型与提示词方案

## 1. 模型使用边界

电商视频生产中的 AI 只负责辅助，不替代人工判断。

当前使用模型的环节：

- 文案分析与生成。
- 音频转文案。
- 字幕配音。
- 音色试听。

模型结果进入资源库或生产草稿前必须经过人工采纳或确认。

## 2. 模型配置

模型配置按三张卡片独立维护：

| 配置卡 | 用途 |
| --- | --- |
| 文案生成 | 参考文案分析、5 条候选生成、继续迭代 |
| 音频转文案 | 抖音短链接、本地视频、本地音频识别为文字 |
| 字幕配音 | 根据正文和音色序号生成旁白音频 |

每张卡片独立保存：

- API 地址；
- API Key；
- 模型 ID；
- 模型类别。

配置完整即使用，不设置启用开关。

## 3. 文案生成提示词原则

### 输入

- 用户输入的一条参考文案，或全局已采纳文案语料快照。
- 此前候选的采纳/不采纳反馈。
- 不采纳原因。

### 分析内容

模型需要分析：

- 语言风格；
- 用词偏好；
- 情感基调；
- 诉求重点；
- 受众年龄、性别、兴趣、消费水平和心理状态；
- 适合的专家角色。

分析结果不提供人工修改。

### 生成规则

- 每轮生成 5 条候选。
- 短文案保持短文案形态。
- 长口播稿保持接近原长度。
- 后续迭代沿用创建任务时冻结的参考资料、分析、专家角色和历史反馈。
- 不采纳原因必须进入下一轮参考。

## 4. 音频转文案

当前使用百炼非实时 `qwen3-asr-flash`。

调用要求：

- 使用 OpenAI 兼容 `chat/completions` 协议。
- 以 Base64 `input_audio` 传入音频。
- 调用前统一压缩为 16kHz 单声道 MP3。
- 单次限制 5 分钟、10MB。
- 排除 `realtime` 和 `filetrans` 协议模型。
- 429、可恢复 5xx 或临时网络错误最多自动尝试 3 次。

识别结果只在人工保存后进入文案库，不创建旁白资源。

## 5. 字幕配音

当前字幕配音根据音色库序号解析 voice 参数。

规则：

- 用户输入 1–597 音色序号。
- 系统解析官方音色目录中的名称、voice、性别、年龄、特质和适用场景。
- 后端再次校验序号合法性。
- 调用 TTS 模型生成音频。
- 使用已知正文和合成音频时长生成字幕时间轴。
- 不反向调用 ASR 识别合成结果。

Qwen-Audio-TTS 和 CosyVoice 使用百炼工作区原生非实时语音合成接口，不能直接拼 OpenAI `/audio/speech`。

## 6. 音色试听

- 音色列表读取不是真实业务调用。
- 首次试听是真实 TTS 调用，必须记录日志。
- 成功试听音频入库保存。
- 后续试听复用库存音频，不重复调用模型。

## 7. 调用日志

真实业务调用必须记录脱敏日志：

- 文案分析与生成；
- 音频识别；
- 字幕配音；
- 音色首次试听。

不记录：

- 连接测试；
- 模型列表读取；
- 音色目录读取。

日志写入失败不得影响业务结果。

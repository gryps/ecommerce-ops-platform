# ____项目运营AI辅助系统产品需求手册

版本：V1.0  
日期：2026-08-11  
适用对象：交给其他AI、开发者、自动化工具搭建者继续开发  
项目阶段：开播前筹备与90天起号验证  

## 1. 产品定位

本系统不是完整ERP，也不是全自动代运营系统，而是一个面向直播电商早期团队的“运营AI辅助系统”。

系统目标是把运营负责人每天需要做的选品、测品、上架准备、直播排品、脚本生成、投流复盘、库存预警、利润测算和日报周报，整理成可录入、可计算、可复盘、可交接的流程。

第一阶段不要求直接调用抖店、巨量千川或平台后台接口。优先采用人工导入、表格上传、截图录入、CSV导入、AI辅助生成的方式，先解决项目内部执行效率和数据判断问题。

## 2. 当前项目业务口径

### 2.1 业务模式

- 一家销售公司负责抖店、销售、收款、采购、售后、纳税和场地。
- 项目团队通过项目合作协议取得项目收益资格。
- 商品方向为国风发饰、簪类及相关饰品。
- 当前重点是90天起号验证，内部执行口径为第1个月1000单、第2个月2000单、第3个月3000单。
- 对投资人可展示6个月成熟期路径，但内部仍以90天为第一道复盘线。

### 2.2 当前基础模型参数

- 采购均价：40元/只。
- 推荐售价：160元/只。
- 单笔订单默认1只。
- 退款率基准：40%。
- 退货中90%可二次销售，10%报废。
- 物流：3元/单。
- 运费险：5元/单。
- 包装：3元/单，首批包装现金支出6000元。
- 平台费：按退款后净GMV的5%测算。
- 投流：默认付费订单占比50%，ROI 5。
- 每月直播：27天。
- 第一阶段人员固定成本模型：内容5000元/月、运营12000元/月、主播2人各10000元/月、客服仓管6000元/月、租金3000元/月、水电物业网络1000元/月。

## 3. 用户角色

### 3.1 项目协调人

关注资金、利润、风险、人员进度、是否达到转全职或止损标准。

### 3.2 运营负责人

系统主要使用者。负责选品测品、店铺资料、直播排品、投流节奏、数据复盘、利润测算和执行推进。

### 3.3 内容负责人

接收拍摄清单、素材需求、短视频脚本、主图卖点、封面文案。

### 3.4 供应链负责人

维护供应商、采购成本、1688链接、库存、质检、退换货条件、补货周期。

### 3.5 主播/场控

接收直播排品表、单品话术卡、福利节奏、逼单提醒、复盘反馈。

### 3.6 客服仓管

接收订单、发货、退货、库存、售后原因和退货可二次销售状态。

## 4. 核心业务流程

### 4.1 选品测品流程

1. 录入候选商品。
2. 补充供应商、采购价、1688链接、图片、规格、库存、发货周期、退换条件。
3. AI生成商品卖点、适用人群、直播话术、标题、主图文案。
4. 运营给出测品等级：A主推、B测试、C备选、D淘汰。
5. 生成拍摄任务。
6. 生成上架资料包。
7. 进入直播排品。
8. 根据直播数据、退款率、利润和库存，形成继续放量、维持测试、降价清仓或淘汰结论。

### 4.2 商品上架准备流程

1. 商品基础资料录入。
2. AI生成标题、短标题、详情页结构、卖点、规格说明、售后说明。
3. 生成主图拍摄清单和详情图拍摄清单。
4. 人工上传到抖店后台。
5. 录入平台链接、商品ID、SKU ID。
6. 系统检查是否缺少价格、库存、主图、详情、运费模板、售后承诺、供应商证据。

### 4.3 直播排品流程

1. 选择本场直播商品池。
2. 标记引流款、主推款、利润款、清仓款。
3. 生成直播排品顺序。
4. 生成每个商品的讲解脚本、价格锚点、优惠策略、库存提醒。
5. 下播后录入每款商品曝光、点击、成交、退款、投流、ROI。
6. 系统输出复盘结论。

### 4.4 投流复盘流程

1. 录入投流计划名称、投放商品、预算、成交金额、订单数、ROI。
2. 系统自动计算利润、边际贡献、是否亏损。
3. 按素材、商品、主播、直播场次维度复盘。
4. 给出继续投、降预算、换素材、停投、换品建议。

### 4.5 库存补货流程

1. 系统根据可售库存、在途库存、退款可二次销售库存、日均销量、采购周期、安全库存天数，计算补货建议。
2. 当库存不足支撑未来7天销售时预警。
3. 当商品退款率过高或利润为负时，禁止自动建议补货，只提示人工复核。

### 5.6.1 商品推广投流子系统

定位：

商品推广投流子系统不是简单记录投流消耗，而是帮助运营负责人判断“哪个商品值得投、投多少、什么时候停、什么时候放量、投流结果如何反馈给选品、内容、主播和库存”。

第一版不直接自动操作巨量千川、随心推或抖音后台，先支持人工录入、CSV导入、截图数据录入和AI复盘。后续在平台规则、账号权限和接口能力明确后，再考虑浏览器自动化或接口化。

#### 5.6.1.1 投流对象

系统应支持至少三类推广对象：

- 直播间推广：目标是进入直播间、停留、商品点击和直播成交。
- 短视频带货推广：目标是通过视频素材带来商品点击、成交或直播间引流。
- 商品卡/货架推广：目标是商品链接点击、转化和成交。

当前项目第一阶段优先级：

1. 直播间推广。
2. 短视频素材测试。
3. 商品卡/货架推广。

原因：项目处于冷启动期，最需要验证主播承接、商品卖点、直播间转化和测品效率。商品卡推广应在商品链接、评价、销量和详情页基础稳定后再加重。

#### 5.6.1.2 投流阶段

系统应将投流计划分为三个阶段：

冷启动测试：
- 单商品或少量商品小预算测试。
- 目标是买数据，不是追求当日利润最大化。
- 重点观察点击、进房、停留、成交、退款和主播承接。

稳定放量：
- 商品连续多场表现达标后进入。
- 允许逐步增加预算。
- 每次预算提升后必须重新观察ROI、退款率和利润。

止损淘汰：
- ROI低、退款高、利润负、主播讲不动或库存周转差时进入。
- 停止放量，必要时降价清仓或下架。

#### 5.6.1.3 投流计划字段

除基础投流字段外，系统还应增加以下字段：

- promotion_type：直播间推广、短视频推广、商品卡推广。
- traffic_stage：冷启动测试、稳定放量、止损淘汰。
- objective：进房、商品点击、成交、直播间成交、素材测试。
- budget_type：日预算、场次预算、商品预算、素材预算。
- planned_budget_yuan：计划预算。
- actual_spend_yuan：实际消耗。
- paid_order_share：付费订单占比。
- raw_roi：按支付GMV计算的表面ROI。
- refund_adjusted_roi：按退款后净GMV计算的退款后ROI。
- estimated_profit_after_ad：扣除采购、物流、运费险、包装、平台费、投流后的估算利润。
- related_live_session_id：关联直播场次。
- related_product_id：关联商品。
- related_material_id：关联素材。
- anchor_id：关联主播。
- operator_decision：继续测试、加预算、维持、降预算、停投、换素材、换商品。
- decision_reason：决策原因。

#### 5.6.1.4 核心计算指标

系统至少计算以下指标：

- 表面ROI = 支付GMV / 投流消耗。
- 退款后ROI = 退款后净GMV / 投流消耗。
- 成交成本 = 投流消耗 / 支付订单数。
- 单品投流后利润 = 退款后净GMV - 采购成本 - 报废成本 - 平台费 - 物流 - 运费险 - 包装 - 投流消耗。
- 单品投流后利润率 = 单品投流后利润 / 退款后净GMV。
- 付费订单占比 = 投流带来订单 / 总支付订单。
- 投流亏损额 = min(0, 单品投流后利润)。

当前项目默认测算：

- 退款率按40%作为基准。
- 支付ROI按5作为目标。
- ROI低于4时触发复盘或暂停放量。
- 退款率超过40%时不得自动建议加大补货。
- 退款率达到或超过45%时触发停止扩张复盘。
- 连续两场单品投流后利润为负，进入人工复核。

#### 5.6.1.5 投流决策规则

系统应根据数据自动给出建议，但最终由运营负责人确认。

继续测试：
- 数据量不足。
- ROI接近目标但样本较小。
- 点击或进房表现较好但成交不足，需要优化主播话术或价格机制。

加预算：
- 连续两场或两天退款后ROI达到目标。
- 单品投流后利润为正。
- 退款率不高于40%。
- 库存能够支撑未来7天销售。
- 主播反馈商品可讲解、用户互动正常。

维持预算：
- ROI达标但退款率接近警戒线。
- 利润为正但库存不足。
- 商品有潜力但素材尚未充分测试。

降预算：
- 表面ROI达标但退款后ROI不达标。
- 成交依赖低价或强福利，利润被压缩。
- 库存不足或售后问题增加。

停投：
- ROI低于4且连续两次未改善。
- 单品投流后利润连续为负。
- 退款率超过45%。
- 商品出现质量、合规、投诉或供应不稳定问题。

换素材：
- 点击率低。
- 进房成本高。
- 商品本身成交不错，但投放素材承接差。

换商品：
- 点击、成交、退款、利润均不达标。
- 主播难以讲解。
- 用户评论反馈弱。

#### 5.6.1.6 每日投流工作台

页面应展示：

- 今日总消耗。
- 今日支付GMV。
- 今日退款后净GMV。
- 表面ROI。
- 退款后ROI。
- 今日投流后利润。
- ROI低于4的计划。
- 利润为负的商品。
- 退款率超过40%的商品。
- 可加预算商品。
- 必须停投商品。
- 明日投流建议。

运营负责人每天需要完成：

1. 录入或导入昨日投流数据。
2. 检查亏损计划。
3. 检查高退款商品。
4. 确认今日保留、加预算、停投的计划。
5. 把投流结果反馈给内容负责人，决定是否换素材。
6. 把投流结果反馈给主播，调整讲解话术。
7. 把投流结果反馈给供应链负责人，决定是否补货或暂停采购。

#### 5.6.1.7 投流和其他模块联动

和商品库联动：
- 商品投流表现会影响商品状态：测试中、主推、清仓、淘汰。

和直播排品联动：
- 投流表现好的商品优先进入下场直播主推位。
- 投流亏损商品不得自动进入主推位。

和内容任务联动：
- 点击率低的商品自动生成“换素材”任务。
- 进房差的直播间计划自动生成“直播间封面/短视频素材优化”任务。

和库存模块联动：
- 达到加预算条件但库存不足时，生成补货提醒。
- 达到停投条件时，禁止自动补货。

和财务模块联动：
- 投流消耗必须进入利润测算。
- 不能只用GMV评价投流效果。
- 所有投流复盘必须同时展示退款后净GMV和估算利润。

#### 5.6.1.8 AI复盘输出

系统应支持一键生成投流复盘，输出格式如下：

- 今日结论：赚钱、微利、亏损、数据不足。
- 最值得继续投的商品。
- 最应停投的商品。
- 需要换素材的商品。
- 需要主播调整话术的商品。
- 需要供应链处理的商品。
- 明日预算建议。
- 风险提醒。

AI复盘禁止只根据GMV下结论，必须同时参考投流消耗、退款率、退款后净GMV、采购成本、平台费、物流、运费险、包装和库存。

核心字段：

- 商品编号

- 退款订单数
- 退款金额

- 退款原因

AI能力：
- 归类退款原因。
- 识别高退款商品。
- 生成客服和商品改进建议。

### 5.8 库存模块

功能：
- 管理可售库存、锁定库存、在途库存、退货库存、报废库存。
- 自动计算补货建议。
- 预警缺货和滞销。

计算逻辑：
- 可用库存 = 可售库存 + 可二次销售退货库存 - 锁定库存。
- 安全库存 = 近7天日均支付订单量 * 采购周期天数。
- 建议补货量 = 未来7天预计销量 + 安全库存 - 可用库存 - 在途库存。

限制：
- 退款率超过40%的商品，不自动建议加大补货。
- ROI低于4的商品，不自动建议加大补货。
- 连续两场直播利润为负的商品，进入人工复核。

### 5.9 财务测算模块

功能：
- 按商品、场次、月度计算利润。
- 计算现金缺口。
- 计算盈亏平衡订单量。
- 计算投流ROI敏感性。

核心参数：
- 售价
- 采购价
- 退款率
- 可二次销售比例
- 报废比例
- 平台费率
- 物流
- 运费险
- 包装
- 投流费用
- 固定成本
- 税费参数

输出：
- 单品毛利
- 单品净利
- 场次利润
- 月度利润
- 现金流缺口
- 盈亏平衡订单量
- 是否触发止损线

### 5.10 日报周报模块

功能：
- 自动生成每日经营日报。
- 自动生成每场直播复盘。
- 自动生成每周经营复盘。
- 自动生成D30、D60、D90复盘材料。

日报内容：
- 今日支付订单
- 今日支付GMV
- 退款后净GMV
- 投流消耗
- ROI
- 退款率
- 毛利
- 估算净利
- 库存风险
- 明日重点动作

周报内容：
- 本周订单趋势
- 商品排名
- 主播表现
- 投流表现
- 退款问题
- 库存问题
- 下周排品建议
- 需要项目协调人决策事项

## 6. 自动化优先级

### P0：必须先做

1. 商品库。
2. 选品测品表。
3. 上架资料包生成。
4. 直播排品表。
5. 单品利润测算。
6. 每日经营日报。

原因：这些功能直接影响开播前准备和90天验证。

### P1：第二阶段

1. 投流复盘。
2. 库存预警。
3. 退款原因归类。
4. D30/D60/D90复盘报告。
5. 拍摄任务协同。

原因：开播后数据会快速变多，人工复盘容易漏掉亏损点。

### P2：第三阶段

1. 浏览器自动化辅助上架。
2. 自动读取平台导出数据。
3. 多主播绩效分析。
4. 多店铺/多品牌扩展。
5. 投资人简报自动生成。

原因：这些功能依赖平台规则、账号权限和稳定数据源，不适合作为第一版核心。

## 7. 不能完全自动化的事项

以下事项必须保留人工确认：

- 最终选品决策。
- 供应商合作确认。
- 商品质量判断。
- 商品定价最终确认。
- 抖店后台最终发布。
- 投流预算放量。
- 停止补货或大额补货。
- 涉及退款、投诉、违规、知识产权、平台处罚的处理。
- 涉及资金、合同、分红、人员退出的处理。

系统可以给建议，但不能替代负责人签字或确认。

## 11. MVP开发建议

第一版可以用最简单的方式实现：

- 前端：网页表单和表格。
- 后端：本地JSON、SQLite或CSV均可。
- AI能力：通过大模型API生成文案、话术和复盘。
- 数据导入：支持CSV复制粘贴。
- 数据导出：支持Markdown、Excel/CSV、PDF。

第一版不建议一开始做复杂权限、不建议直接打通平台接口、不建议做全自动上架。

## 12. 第一版验收标准

系统达到以下标准即为可用：

1. 能录入50个候选商品。
2. 每个商品能生成上架资料包。
3. 每个商品能生成直播话术卡。
4. 能生成一场直播排品表。
5. 能录入直播后的订单、GMV、退款和投流数据。
6. 能自动计算单品利润和场次利润。
7. 能输出每日复盘。
8. 能标记商品继续主推、继续测试、降价清仓或淘汰。
9. 能提示库存不足和高退款风险。
10. 能导出给团队看的执行表。

## 13. 开发时必须注意的边界

1. GMV不等于利润，也不等于到账现金。
2. 退款率必须参与利润测算。
3. 退货报废率是退货商品中的10%，不是全部订单的10%。
4. 投流ROI不能只看成交额，必须看退款后净GMV和利润。
5. 库存补货不能只看销量，还要看退款率、ROI和现金流。
6. AI生成内容只能作为初稿，涉及平台规则、广告法、售后承诺、知识产权时必须人工审核。
7. 系统不能自动承诺投资回报、不能替代合同、不能替代财务和税务判断。

## 14. 交给其他AI开发时的执行提示

请基于本PRD开发一个直播电商运营AI辅助系统。优先完成MVP，不要一开始追求全自动平台操作。系统应围绕商品库、选品测品、上架资料包、直播排品、投流复盘、库存预警和日报周报展开。第一版允许人工导入数据，允许人工复制AI生成结果到抖店后台。所有财务测算必须区分GMV、退款后净GMV、投流费用、平台费、采购成本、物流、运费险、包装、固定成本和税费假设。系统输出应能让运营负责人每天知道：今天卖得怎么样、哪些品值得继续推、哪些品亏钱、是否需要补货、明天直播怎么排品。

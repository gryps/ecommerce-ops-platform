# 混剪框架库业务与实现规范

> 历史兼容说明：本文中的音乐卡点、自动生产和系统内成片规则已于 2026-08-01 退役。
> 当前资源库与剪映草稿规则以 `docs/JIANYING_DRAFT_WORKFLOW_REQUIREMENTS.md` 为准。

> 状态：2026-07-28 工程开发完成，待真实业务验收。本文取代旧“六类模板库存”“标题字幕组合模板”
> 与“框架三个月不得复用”等规则；历史文档仅用于追溯，不再作为实现依据。

## 1. 核心定义

- 一级功能正式命名为“混剪框架库”。
- 框架是一种成片表达形式，不直接区分通用或产品专用；是否专用只由实际文案是否指向产品决定。
- 框架直接保存标题视觉样式、字幕视觉样式、音乐兼容规则、卡点结构、可手工调整的固定成片时长和混音参数。
- 字体从运行机器上实际存在的中文字体清单选择，名称和真实文件路径直接保存在框架文字样式中；不建立字体库存，也不要求用户提供字体文件。
- 旁白是可选增强项；需要时由已采纳文案调用统一配置的“旁白配音”模型生成，不建立音色库存，也不在框架内重复配置模型音色。
- 具体画面镜头在生产时从产品资料库自动选取；框架只定义镜头切换时刻，当前片段间使用硬切。
- 取消标题、字幕、音乐、贴纸、特效、转场六类组件模板库存。贴纸、特效和转场暂不属于框架。

## 2. 资源结构

混剪框架库使用三个二级标签：

1. 框架
2. 文案
3. 音乐

“文案”包含标题库、旁白文案库和文案组合：

- 标题与完整旁白分别生成、分别审核，也可人工输入。
- 只有“已采纳”内容可以组成框架文案组合。
- 一个文案组合只属于一个框架；标题或旁白内容本身可被多个框架引用。
- 组合允许只有标题或只有旁白，但不能两者都为空。
- 标题和旁白同时存在时必须语义匹配；指向不同产品时禁止组合。
- 一条产品专用组合只能绑定一个产品组；生产时优先专用组合，再使用通用组合。
- 文案组合按人工顺序依次使用，准确文字组合三个月内不得重复。
- 实际需要持续积累的生产资产是文案和背景音乐；标题/字幕样式直接属于框架，本项目不扩展独立样式预设库。

## 3. 框架编辑器

- 产品定位是“面向批量生产的结构化混剪框架编辑器”，不是通用非线性剪辑软件，也不以完整复刻剪映为目标。框架编辑器负责规则、文案、版式、时间关系、自动检查与批量复用；复杂特效和逐帧精修留给外部专业工具。
- 使用独立全屏编辑器。
- 编辑器采用中间 9:16 画布、底部多轨时间线的主工作区；文案/音乐/发布检查放入可收起的左侧覆盖抽屉，文字与位置属性放入可收起的右侧覆盖抽屉。两侧抽屉不永久占用画布宽度，关闭后通过画布边缘按钮恢复，并可拖动各自靠近画布一侧的竖向边框调整宽度。资源抽屉内部用页签切换；属性抽屉采用有最小列宽约束的响应式表单，避免字段重叠、覆盖或被压成异常窄列。窄屏不同时展开两侧抽屉。
- 覆盖抽屉展开时，中央画布按左右抽屉的实时宽度计算未遮挡可见区域；画布和缩放控件只在该区域内居中、适配与滚动，不得被框架属性或素材抽屉覆盖。两侧剩余宽度不足 380px 时只保留最后打开的一侧抽屉。
- 编辑器界面采用适合高分辨率显示器的独立字号层级，不复用库存表格的紧凑小字号；属性中的内容轨道复选项固定采用“复选框 + 名称”横向成组布局，不允许被表单网格拆列。
- 固定抖音竖屏 9:16、1080×1920 设计与渲染基线，并显示平台遮挡区和内容安全区。
- 画布使用固定设计坐标与独立预览缩放：默认按中央可用区域自动等比适配，支持 50%—200% 手工缩放和一键恢复适合窗口。标题、字幕、安全区及元素选择框随竖屏整体同比缩放，缩放不修改生产布局数据；拖动和缩放元素仍按 1080×1920 百分比坐标回写。缩放或窗口尺寸变化后自动将竖屏重新置于可滚动视口中心。
- 框架属性与画布共享同一编辑状态；位置、范围、字体、字号、颜色、间距、对齐、描边、阴影、旋转和缩放参数调整后立即反映到竖屏画布，持久化继续使用延迟自动保存。
- 竖屏画布不设置独立时间轴或时间滑杆。当前预览时刻只由底部多轨时间线的统一播放头决定；时间标尺支持点击和拖动定位，播放头贯穿画面、标题、字幕与背景音乐轨，画布按该时刻显示实际应出现的文字。
- 画布逐条载入框架绑定的标题和字幕展示副本，支持逐个组合比对、修改、拖动位置、四角缩放及精确坐标同步；修改展示副本不污染全局文案资产。
- 标题和旁白字幕分别保存字体、字号、粗斜体/下划线、颜色、字间距、行间距、
  文字对齐、描边、阴影、缩放、等比锁定、坐标、旋转、画布对齐、入场和退场动画。
- 标题内容库以换行保存语义短句；人工录入可用 Enter 明确断行，模型或旧数据中的逗号、分号短句在入库时自动规范为多行。换行只表示语义结构，不参与文案重复差异判断。
- 标题进入框架组合后生成框架专用的展示行副本。框架保存标题默认样式，每个展示行可单独覆盖字体、字号、颜色、字间距、行间距、对齐、描边、阴影、旋转及动画字段；未覆盖字段继承框架默认样式，可一键恢复默认。逐行文字或样式修改不回写全局内容库。
- 画布按行呈现并允许直接选中某一标题行编辑样式；正式渲染为每一行创建独立文字层，保证各行字体、字号、颜色、对齐和描边等渲染属性互不影响。
- 字幕在用户定义的区域内按真实字体度量换行；放不下时按语义和语音停顿拆屏。
- 时间线至少包含画面镜头、标题、字幕和背景音乐四轨；标题、每条字幕和背景音乐的展示/覆盖时长只在多轨时间线及其精确数字输入中确定。标题、字幕和背景音乐时间块均支持整体拖移及左右端裁切。
- 标题、字幕与背景音乐统一使用成片时间标尺。背景音乐的源音频截取区间与成片出现区间分别保存；音乐块可以只覆盖成片中的一段，并可整体前移或后移。整体拖动只改变成片位置，不改变源音频；拖动左右端同时调整对应的成片边界和源片段边界。时间块同时标注成片区间与源音频区间，可双击试听当前源片段。精确节拍、重拍、段落、能量峰、推荐切点、缩放滚动和吸附继续按后续优先级完善。
- 画布、样式、时长、标题和字幕时间线采用延迟自动保存，顶部明确显示保存状态；编辑会话提供撤销/重做按钮以及 Ctrl+Z、Ctrl+Y 快捷键，关闭前立即补存尚未触发延迟保存的修改。

### 3.1 后续能力优先级

1. 继续提高最终渲染一致性：真实字体度量、自动换行、低清预览与 FFmpeg 成片一致。
2. 强化批量自动化：按文案长度自动分行与分配字幕时长，检测安全区溢出，自动适配固定时长，批量替换文案后重新排版。
3. 完善音乐生产辅助：真实波形、节拍、重拍、推荐切点、缩放滚动和吸附。
4. 为外部精修提供预览视频、字幕文件和时间清单等出口；是否支持外部编辑器草稿交换另行评估。

当前不扩展通用多轨剪辑、特效市场、蒙版抠像、任意关键帧、专业调色混音、贴纸滤镜和粒子系统。

## 4. 音乐与卡点

- 音乐资源全局复用，分析结果不因框架重复计算。
- 音乐保存 BPM、节拍、重拍、起音、能量峰、段落、乐句边界、拍号、波形、置信度和推荐切点。
- 框架保存抽象节奏签名和兼容阈值，不保存某一首歌的绝对时间结构。
- 加入框架的音乐必须达到兼容阈值并经人工试听，状态为“可生产”后才能使用。
- 音乐池可试听待加入资源和框架已选片段；音频通过受权限保护的真实文件接口读取。修改片段开始或结束时间后自动回到“待试听”，需要重新人工确认。
- 发布检查和生产任务准备必须校验已试听音乐的源片段与成片出现区间均有效，但不要求音乐覆盖完整成片。任何框架时长修改都会使完整低清预览和框架可生产状态失效，但不会自动延长或移动音乐；调整后需重新确认时间线、预览并启用。
- 框架音乐池按人工顺序依次使用；音乐没有一周或三个月复用间隔。
- 音乐无需覆盖完整成片，也不自动循环或拼接。渲染按成片出现区间延迟音乐入点，并在区间结束时停止；源片段长度只需足以支持其成片出现时长。
- 音乐不可用时只能选择同一框架中已审核的兼容音乐；无兼容音乐则只暂停该框架。

## 5. 旁白、字幕与混音

- “旁白配音”模型在模型配置中统一保存模型和音色；框架不维护音色资源。未启用或未配置旁白不得阻塞无旁白成片发布。
- 旁白从成片 0 秒开始；旁白结束后背景音乐继续。
- 字幕时间线由配音模型生成的真实旁白音频进行语音对齐，允许人工调整。
- 框架文案组合提供“模型配音”和右侧字幕时间轴校准界面；系统按分段时长比例给出
  初始时间，人工可逐段修正开始、结束时间。
- 字幕组合必须具备覆盖全部有序分段的展示时间线才能审核通过；只有实际选择生成旁白时才要求冻结音频。
- 修改旁白文字后重新审核、重新调用模型生成语音和时间线；只修改分段或时间时不重新生成语音。
- 审核通过的语音与字幕时间线冻结为组合审核产物，正式生产直接复用。
- 背景音乐与旁白共存；旁白期间音乐自动压低，旁白结束后恢复。
- 框架保存正常音乐 dB、压低后 dB 和压低/恢复渐变时长；最终混音统一做响度与峰值规范化。

## 6. 状态、版本与热点

- 框架状态为草稿、待审核、可生产、已停用。
- 发布检查一次性返回全部问题，包括文字安全区与展示时间、文案、音乐版权、兼容音乐、卡点、素材容量和完整低清预览；旁白配置不是统一发布条件。
- 已投入使用的生产字段不原位覆盖；修改时创建新版本。
- 新版本复制文案组合和兼容音乐关系，但全部回到待审核/待试听状态。
- 历史回滚创建新的草稿版本。
- 热度保留未标记、低、中、高；热点迭代创建独立草稿副本，继承父框架热度和配置。
- 只有从未引用的草稿可永久删除，其余框架只能停用。

## 7. 预览、生产与去重

- 完整低清预览使用真实已审核文案、旁白音频、兼容音乐和产品资料库镜头。
- 预览与正式渲染共用串行队列，但不计入生产使用或三个月去重。
- 框架本身、文字样式、配音模型音色和音乐均无固定复用间隔。
- 成片三个月去重以画面镜头组合为主；三个月内已用于成片的镜头占比不得超过 30%。
- 精确标题+旁白组合三个月不得重复。
- 同一产品的同优先级框架轮换使用，避免连续采用同一种表达形式。
- 兼容音乐卡点数量决定所需差异化镜头数量；素材不足时跳过该任务并报告缺口，不暂停其他任务。
- 无人值守启用后每日自动编排，所有正式任务按队列串行渲染。
- 生产任务状态 `awaiting_template` 的业务文案统一为“待满足生产条件”，不得误写成“待配置模板”。任务列表应实时显示当前匹配框架的具体阻塞条件，包括时长不匹配、音乐区间无效或未试听、文案、字体、预览或发布状态；条件修复后原任务可重新准备，不要求删除重建。

## 8. 数据切换范围

本轮允许清空：

- 旧六类模板和旧框架数据
- 旧文案、旧成片、旧生产任务
- 旧素材使用/文案使用记录
- 旧模型调用调试日志
- 旧输出成片文件

必须保留：

- 产品资料库、产品组和背景组
- 素材批次、素材关系和原始视频
- 已获取的音乐文件与音乐资源
- 已有字体文件（只保留文件本身，不保留字体库存）
- 所有业务模型配置/API 设置
